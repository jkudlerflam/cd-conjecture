# C32: Make the 23-letter route-A chain mobile, and bound its scales

Read `../../specs/_routeA_background.md`, `../../contrib/routeA_spatial/README.md` (an explicit 23-letter computation-free route-A chain with exact U(1) and parity, an exactly degenerate code, zero first order, and bands that all cross with distinct centres through n = 3), `../../contrib/routeA_compile/README.md` (a related number-conserving switch cell), `../work_C13/RESULT.md`, `../work_C20/RESULT.md`, `../work_C25/RESULT.md` and `../work_C8/` (mobile wrapper, padding transport, helix equalizer) first. If `PROGRESS.md` exists in your folder, continue from it.

**Your task.**
1. **Mobility.** The 23-letter cells are frozen and their payload grows with cell length, so C20's mobile pair (cells of two adjacent lengths carrying the same payload) is not available. Build a mobile version: for example separate the cell into a payload core of fixed flavour count and a padding region that absorbs length changes (C8's padding transport), or let the flavour count be set by something other than the total length. Show the second-order logical bond is equal (or equalizable) for the two lengths, the length fluid is free at leading order, and U(1) and parity stay exact. Give the alphabet and d0 of the mobile chain.
2. **The band argument for every n.** The README proves that the hopping matrix tends to a phase times a positive Gram matrix only in the limit of a large express energy, and checks finite values numerically through n = 4. Give a finite-parameter argument (or an explicit parameter schedule in n) that all n bands cross a common field with distinct centres and Sidon-compatible margins.
3. **Scales.** The narrowest band shrinks by a factor of about 50 to 100 per flavour. Write the full hierarchy as a function of n and confirm it closes at each fixed n with all couplings fixed and nonzero.
4. Verify the key claims by exact diagonalization of two and three cells at n = 1, 2 for the mobile version.

Rules: theoretical-physics standard, finite-dimensional statements proved. Tag every claim as proved, numerical (with sizes), heuristic, or assumed. Do not put probabilities, odds or percent-confidence estimates in any file. Python (numpy and scipy) only, inside your folder; no network; never modify files outside your folder; keep each computation to minutes. Write prose plainly, without em-dashes. Keep `PROGRESS.md` updated and write `RESULT.md` at the end.
